TournéeVéto & GitHub Copilot

De l'idée au POC Blazor publié sur GitHub Pages, puis sur le poste Windows (WPF) et le mobile (.NET MAUI), en maîtrisant toutes les fonctionnalités de GitHub Copilot : instructions, skills, agents personnalisés, orchestration, optimisation du contexte et des tokens.

Développeurs .NET · ~80 %

Workspace & contexte, maquettes Stitch, skills, agents, orchestration, optimisation, tests, CI/CD. Stack : .NET 10, C#, Blazor WebAssembly (PWA), IndexedDB via JS interop, xUnit, bUnit, Playwright pour .NET ; WPF et .NET MAUI via Blazor Hybrid au module 10.

Product Owners & Architecture · ~20 %

PRODUCT.md, périmètre du MVP, backlog GitHub Issues via MCP (les critères Gherkin servent de spécification), ADR, recette sur l'URL publique, backlog V2 prêt pour les agents.

Le produit : TournéeVéto, l'application du vétérinaire en visite d'élevage laitier. Tournée du jour, fiche élevage et import du troupeau (CSV), grille de régie calculée (vêlages, diagnostics de gestation, tarissements, cellules somatiques), bilan de biosécurité noté avec ses pratiques prioritaires, photos, rapport de visite imprimable, PWA hors ligne (l'étable n'a pas de réseau). 100 % navigateur : aucun backend, aucun Docker, publiée sur GitHub Pages. Les mêmes composants tournent ensuite dans une application WPF et une application MAUI.

Produit, données et règles métier fictifs et simplifiés, à but pédagogique : ils ne remplacent ni un logiciel vétérinaire ni l'avis d'un médecin vétérinaire.

Outil unique : GitHub Copilot, dans VS Code (avec C# Dev Kit) ou Visual Studio 2026, au choix, complété par Google Stitch pour les maquettes. Les labs sont écrits pour VS Code ; un encadré Dans Visual Studio signale chaque différence. Certaines fonctionnalités (skills, hooks, Chat Debug View) peuvent n'exister que dans VS Code : faites alors ces labs dans VS Code, les fichiers de .github/ sont communs au dépôt et profitent aux deux IDE. Fonctionnalités vérifiées en octobre 2026 ; Copilot évolue vite, vérifiez la documentation officielle avant chaque session.

Ici, pas de prompt prêt à copier

Savoir écrire le bon prompt, c'est LA compétence. La plupart des labs vous donnent une amorce à compléter, des indices à débloquer un par un et des critères de réussite pour vous auto-évaluer ; d'autres sont des QCM interactifs corrigés immédiatement.

Les 5 ingrédients d'un bon prompt Copilot

  1. Rôle : « Agis comme… » ou, mieux, le bon agent sélectionné.
  2. Contexte ciblé : 2 ou 3 fichiers nommés avec #, pas toute la solution.
  3. Une seule tâche, bornée (« uniquement… », « n'écris pas… »).
  4. Contraintes & format de sortie : quel projet, quel fichier, quel format, quelle longueur.
  5. Critère de fin : la commande qui prouve que c'est terminé (dotnet test…).

Prérequis

  • VS Code + C# Dev Kit, ou Visual Studio 2026 (charges de travail « Développement web » et « .NET desktop »), avec GitHub Copilot (licence payante recommandée : crédits IA et serveurs MCP)
  • SDK .NET 10, Git, et Node.js 22 LTS (uniquement pour lancer le serveur MCP Playwright)
  • Un compte GitHub (dépôt public ou Pages activé) et un compte Google pour Stitch
  • Windows 10 ou 11 pour l'application WPF (module 10) ; pour le bonus MAUI, la charge de travail maui installée avant la formation (téléchargement volumineux)
  • Une tablette ou un téléphone pour tester la PWA hors ligne
  • Licence Copilot Business/Enterprise : politique « MCP servers in Copilot » activée par l'administrateur (désactivée par défaut) ; dossier du projet approuvé dans VS Code (Workspace Trust)
  • Copilot est facturé à l'usage : prévoir un budget de crédits par apprenant (le module 7 apprend à le réduire).
